
Комбинационная логика (always_comb / Провода и MUX)

• Управление шагом счета: В зависимости от состояния mode_select, формируется значение шага инкремента (+1 или +2).
• Мультиплексор сброса: На основе сигнала pulse_in формируется следующее значение для регистра счетчика. Если pulse_in == 1, подготавливается 0 (сброс на новый круг). Если pulse_in == 0, к текущему значению счетчика прибавляется выбранный шаг счета.
• Вычисление среднего: Значения двух регистров истории складываются. Для исключения потери старшего бита переноса при сложении двух 8-битных чисел, операция должна выполняться в 9-битной сетке (sum_ints = last_int_1 + last_int_2). Деление на 2 реализуется сдвигом результата на 1 бит вправо.
• Флаг переполнения: Логика должна фиксировать, если счетчик времени достиг своего максимального значения (8'hFF), а импульс pulse_in так и не пришел.
• Синхронизация: Все триггеры и регистры обновляются строго по фронту posedge clk. При rst_n == 0 все внутренние регистры и выходы сбрасываются в 0.
• Регистр счетчика (timer_reg): Каждый такт защелкивает значение, подготовленное комбинационным MUX сброса.
• Сдвиговый конвейер истории (last_int_1, last_int_2): Работает по принципу Clock Enable. Когда pulse_in == 1, оба регистра одновременно фиксируют данные: last_int_1 забирает текущее значение счетчика, а last_int_2 забирает старое значение из last_int_1.
• Стабильность выходов: Выходные сигналы average_val и overflow_alert должны пропускаться через выходные триггеры, чтобы исключить комбинационный глитч (дребезг сигналов) на выходах модуля.
